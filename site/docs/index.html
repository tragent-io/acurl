acurl documentation

acurl requests a URL once per agent profile and compares each response with a real Chrome request: status, WAF challenge, robots.txt rule, visible-text similarity and product data. Results come out as a table or as JSON, SARIF, JUnit, Markdown, CSV or HTML, and the exit code follows --fail-on.

Installation

acurl is a single static binary for macOS, Linux and Windows (amd64 and arm64).

MethodCommand
Homebrewbrew install tragent-io/tap/acurl
Shell scriptcurl -fsSL https://acurl.dev/install.sh | sh
Go 1.26+go install github.com/tragent-io/acurl/cmd/acurl@latest
npmnpx @tragent/acurl <url> or npm i -g @tragent/acurl
Dockerdocker run --rm ghcr.io/tragent-io/acurl <url>
BinariesGitHub Releases, with checksums, SBOMs and cosign signatures

Check the install with acurl --version. Shell completions: acurl completion zsh > "${fpath[1]}/_acurl" (see completion).

Quick start

Point acurl at any page. A scheme is optional: https:// is assumed.

$ acurl shop.example/products/wool-runner
Fetching https://shop.example/products/wool-runner with 23 profiles...

PROFILE            STATUS  TIME    RESULT             DETAILS
Chrome (Browser)   200     412ms   allowed            Wool Runner | Example Store
ChatGPT-User       403     51ms    challenged         challenge: Cloudflare
Claude-User        200     388ms   allowed            OK
OAI-SearchBot      200     97ms    cloaked            31% similar to browser
GPTBot             200     365ms   robots-disallowed  robots.txt: disallowed
...

AI readiness 71/100 (C)
  ✗ AI assistants can fetch the page            16.7/25  ChatGPT-User (challenged)
  ✓ Content is in the HTML without JavaScript   15.0/15
...
How to improve
  1. AI assistants can fetch the page
     Allow ChatGPT-User, Claude-User and Perplexity-User in your WAF or bot-management rules...

The exit code is 1 because an agent was challenged. Change that with --fail-on.

Reading the output

ColumnMeaning
PROFILEThe agent acurl pretended to be. Chrome (Browser) is the baseline everything is compared with.
STATUSFinal HTTP status after redirects. - for robots.txt-only tokens, ERR for network failures.
TIME / SIZETotal request time and body size (capped by --max-body).
RESULTThe verdict for this agent.
DETAILSWhy: the WAF vendor, similarity to the browser, robots.txt and meta directives, product price differences, redirects or the error.

Below the table: the AI readiness score with each check, and a fix for every failed check.

Usage patterns

Check only the agents you care about

acurl --category ai-assistant,ai-search shop.example     # categories keep the browser baseline
acurl --agents "Chrome (Browser),ChatGPT-User,Claude-User" shop.example
acurl profiles list                                      # every profile and its category

See exactly what an agent missed

acurl --diff OAI-SearchBot shop.example/products/1      # visible-text diff vs the browser, on stderr
acurl -f html -o report.html shop.example/products/1     # shareable report with diffs

Raw output for scripts

acurl -q -f json shop.example | jq '.results[] | select(.classification != "allowed") | .profile'
acurl -q -f json shop.example | jq '.score.value'
acurl -q -f csv  shop.example > agents.csv

Robots and llms.txt without fetching the page

acurl robots shop.example/products/1
acurl robots -f json shop.example | jq '.agents[] | select(.allowed | not) | .token'

Whole site

acurl batch urls.txt                                     # one URL per line, # comments allowed
acurl batch --sitemap auto:shop.example --limit 100      # sitemaps listed in robots.txt
cat urls.txt | acurl batch -f junit -o acurl.xml

Staging, logins and regions

acurl -H "Cookie: country=US" -H "Authorization: Basic dXNlcjpwYXNz" staging.shop.example
acurl --proxy socks5://127.0.0.1:1080 shop.example       # check from another network
acurl -k https://localhost:8443                          # self-signed certificates

Isolate the user agent

acurl --tls chrome shop.example     # bots use Chrome's TLS fingerprint too: only the UA differs
acurl -I shop.example               # HEAD requests: status and headers only

Verdicts

Each result gets exactly one verdict, checked in this order:

VerdictWhenFails by default
errorThe request failed (DNS, TLS, timeout, reset)yes, exit 2
challengedA known WAF challenge or block page: Cloudflare, Akamai, DataDome, PerimeterX, Imperva, Kasada, AWS WAF, Sucuri or a CAPTCHA on an error pageyes
rate-limitedHTTP 429. Retry-After is parsed as seconds or a date.no
blockedAny 4xx or 5xx statusyes
robots-disallowedrobots.txt disallows the agent's token for this URLno
cloakedAllowed, but the visible text is less than 50% similar to the browser's (--cloak-threshold)no
allowedEverything else

Agent profiles

A profile is a user agent string, optional headers and the robots.txt token the agent obeys. The catalog has 23 profiles in six categories:

CategoryProfiles
browserChrome (Browser), the baseline
ai-assistantChatGPT-User, Claude-User, Perplexity-User, MistralAI-User, DuckAssistBot
ai-searchOAI-SearchBot, Claude-SearchBot, PerplexityBot, Amazonbot
ai-trainingGPTBot, ClaudeBot, Claude-Web, anthropic-ai, Meta-ExternalAgent, Bytespider, CCBot, Google-Extended*, Applebot-Extended*
searchGooglebot, Bingbot, Applebot
othercurl (Baseline)

* robots.txt-only tokens: checked against robots.txt, never fetched.

Browser profiles use Chrome's TLS, HTTP/2 and client hints. Bot profiles send only their own headers over Go's TLS stack, like most real crawlers. Bring your own catalog with --profiles my-profiles.yaml:

profiles:
  - name: "InternalBot"
    category: other
    user_agent: "InternalBot/2.0 (+https://example.com/bot)"
    robots_key: "InternalBot"
    headers:
      X-Team: "growth"

AI readiness score

A 0-100 score from weighted checks that only use what was observed in the run. Checks that don't apply (not a product page, no agents of that category) are skipped and the rest re-weighted. A URL that looks like a product page is expected to have Product data; override with --page product or --page other. Blocking training crawlers costs nothing: that is a business decision.

CheckWeight
AI assistants can fetch the page25
AI search crawlers can fetch the page20
Content is in the HTML without JavaScript15
No bot challenges for AI agents10
AI agents see the same content as browsers10
Product structured data is present (product pages)15
Search and AI search may index the page (no noindex)15
AI agents see the same price and availability10

Grades: A 90+, B 80+, C 65+, D 50+, F below. Pages are not scored when the browser request fails, gets an HTTP error or a challenge, or the URL is not HTML; acurl says which.

Exit codes and --fail-on

CodeMeaning
0Nothing matched the --fail-on policy
1Something matched (for example an assistant was blocked)
2A request failed, or acurl was used incorrectly

The default is --fail-on blocked,challenged,error. Combine blocked, challenged, rate-limited, cloaked, robots, error and score<N, or use none.

acurl --fail-on 'blocked,challenged,cloaked,score<80' shop.example

Quote the value in a shell when it contains score<N, or the shell reads < as an input redirect.

CI and GitHub Actions

- uses: tragent-io/acurl@v1
  with:
    urls: |
      https://staging.shop.example/
      https://staging.shop.example/products/best-seller
    fail-on: blocked,challenged,score<80

The action installs acurl, writes a job summary, and uploads SARIF to code scanning when the job has security-events: write. Without the action:

go install github.com/tragent-io/acurl/cmd/acurl@latest
acurl batch urls.txt -f sarif -o acurl.sarif --fail-on blocked,challenged

Results from cloud runners can differ from your laptop's: many WAFs score datacenter IP ranges. If the browser baseline is challenged, the runner is being blocked, not the agents.

robots.txt and llms.txt

acurl robots fetches only robots.txt and llms.txt, and reports per agent:

  • allow or disallow using Google's robots.txt matcher, with RFC 9309 failure rules (4xx allows all, 5xx or an unreachable server means full disallow)
  • Content-Signal directives such as search=yes, ai-train=no
  • sitemaps listed in robots.txt
  • /llms.txt and /llms-full.txt: presence, title, sections, links and format problems

The main command also reads X-Robots-Tag and <meta name="robots">, including agent-specific tags like <meta name="GPTBot" content="noindex">.

JavaScript rendering

Most AI agents do not run JavaScript. acurl flags client-rendered shells (an empty app root, a "please enable JavaScript" notice, almost no text). With --render, it loads the page in a local headless Chrome and reports how much visible text only exists after scripts run:

$ acurl --render shop.example
JavaScript rendering
  64% of the visible text only appears after JavaScript runs (812 -> 2254 chars).
  Agents that do not run JavaScript miss it.

Rendering needs Chrome or Chromium installed. On Ubuntu 23.10+, Chrome's sandbox needs sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0. Inside a container, set ACURL_CHROME_NO_SANDBOX=1 instead.

Watching for changes

acurl watch shop.example --interval 1h \
  --webhook https://hooks.slack.com/services/... --webhook-format slack

# from cron: run once, compare with the last run, alert on changes
acurl watch shop.example --interval 0 --state /var/lib/acurl/state.json --webhook https://ops.example/hook

Reports every change in an agent's verdict and score moves of at least --min-score-delta points.

Web Bot Auth signing

Sign bot-profile requests with HTTP Message Signatures (RFC 9421, Ed25519), as proposed by Web Bot Auth. Use it to test your verifier or your own agent:

acurl keygen -o mybot.key           # prints the key directory JSON to publish
acurl --sign mybot.key --signature-agent https://bot.example shop.example

Requests carry Signature-Agent: sig1="https://bot.example", Signature-Input (covering @authority and "signature-agent";key="sig1", with created, expires, nonce and tag="web-bot-auth") and Signature, following the current Web Bot Auth draft. Signing is verified against the RFC 9421 Ed25519 test vector.

Watching AI CLI traffic

acurl tap shows what Claude Code, Codex, Gemini CLI or Grok sends to its model provider and what comes back, one line per exchange, like tcpdump. Run it in one terminal and keep using the CLI in another:

# terminal 1
acurl tap

# terminal 2
eval "$(acurl tap env)"      # once, or in ~/.zshrc / ~/.bashrc
claude
21:21:49 #1 anthropic HEAD /api/hello 200 565ms 0B > 0B
21:21:50 #2 anthropic POST /v1/messages?beta=true claude-opus-5-5 200 1.639s 70.0KB > 1.5KB stream

Each CLI is pointed at a local proxy through the base URL variable it already supports, so no CA certificate is installed. The wrappers from acurl tap env (bash, zsh, fish, PowerShell) only use the proxy while it is running. The first acurl tap starts the proxy in the background; quitting the viewer leaves it running, so a tapped CLI keeps working.

CLIVariablesNotes
claudeANTHROPIC_BASE_URLAPI key and claude.ai login
codexOPENAI_BASE_URLAPI key login only; ChatGPT login bypasses the base URL
geminiGOOGLE_GEMINI_BASE_URL, CODE_ASSIST_ENDPOINTGemini API key and Google login; not Vertex AI
grokGROK_CLI_CHAT_PROXY_BASE_URLGrok Build CLI with grok.com login
acurl tap --bodies              # request and response bodies under each line
acurl tap -w session.jsonl      # every exchange as a JSON line
acurl tap --redact "Acme Corp"  # remove extra strings
acurl tap status                # is the proxy running
acurl tap stop                  # stop it (quit tapped CLIs first)

API keys, tokens, cookies and key= parameters are replaced with [redacted], and each removal is recorded. Prompts and model output are not redacted, so treat session files like shell history. The proxy only listens on loopback and refuses browser requests. Streams pass through as they arrive; WebSockets pass through with only the handshake recorded. See the full guide.

Configuration

acurl init writes a commented .acurl.yaml. Any flag can be set by its long name. Precedence: flags, then ACURL_* environment variables, then the config file.

category: [ai-assistant, ai-search]
fail-on: blocked,challenged,score<75
timeout: 20s
header:
  - "Cookie: country=US"

acurl looks for ./.acurl.yaml, then ~/.config/acurl/config.yaml, or the file given with --config. Unknown keys are an error, so typos never pass silently.

Go library

import "github.com/tragent-io/acurl/pkg/acurl"

c, err := acurl.New(acurl.Options{BlockPrivate: true})
if err != nil { return err }
rep, err := c.Check(ctx, "https://shop.example/products/1")
if err != nil { return err }
fmt.Println(rep.Score.Value, rep.Summary.Blocked)

acurl serve

Run the acurl web UI and JSON API locally

acurl serve [flags]

serve starts a local web UI for running checks in the browser, plus the JSON API it uses (POST /api/check, GET /api/robots, GET /api/profiles). Requests to private and internal addresses are blocked unless --allow-private is set, because anyone who can reach the server can make it fetch URLs. The server only answers to localhost and --allowed-host names, refuses cross-origin API calls and requires JSON bodies, which stops DNS rebinding and CSRF.

acurl tap

Watch the API requests AI coding CLIs make, like tcpdump

acurl tap [flags]

tap prints every request that Claude Code, Codex, Gemini CLI or Grok sends to its model provider, with the response it got back. Run it in one terminal, and run the CLI in another after loading the wrappers from `acurl tap env`. The wrappers point each CLI at a local proxy through its base URL variable while the proxy is running, and leave it alone when it is not. Traffic is plain HTTP on loopback and HTTPS to the provider, so no CA certificate is needed. The first `acurl tap` starts the proxy in the background and keeps it running after you quit, so CLIs started through it keep working. Stop it with `acurl tap stop`. API keys, tokens and cookies are replaced with [redacted] in everything tap prints or writes. Add other strings to remove with --redact.

FlagDefaultDescription
--bodiesprint request and response bodies under each line
--keep-credentialsdo not redact API keys, tokens and cookies
--listen string127.0.0.1:8899loopback address the proxy listens on
--max-body int1048576bytes of each body to keep; the rest is counted, not stored
--redact string, repeatableextra string to replace with [redacted] (repeatable)
-w, --write stringappend every exchange as JSON lines to this file (- for stdout)

Examples

  # terminal 1
  acurl tap

  # terminal 2
  eval "$(acurl tap env)"
  claude

  acurl tap --bodies
  acurl tap -w session.jsonl
  acurl tap stop

acurl tap env

Print shell functions that route AI CLIs through acurl tap

acurl tap env [cli...] [flags]

env prints shell functions named after each CLI (claude, codex, gemini, grok). Each one checks whether the acurl tap proxy is running. If it is, it runs the CLI with its base URL variable pointing at the proxy; if not, it runs the CLI unchanged. Load them in the current shell with eval, or add that line to your shell's rc file. The shell is taken from $SHELL unless --shell is set.

FlagDefaultDescription
--listlist the supported CLIs and the variables they use
--listen string127.0.0.1:8899address the proxy listens on
--shell stringshell to write for: bash, zsh, fish, powershell (default from $SHELL)

Examples

  eval "$(acurl tap env)"
  eval "$(acurl tap env claude)"
  acurl tap env --shell fish | source
  acurl tap env --shell powershell | Out-String | Invoke-Expression
  acurl tap env --list

acurl watch

Re-check URLs and report when agent access changes

acurl watch <url>... [flags]

watch checks URLs repeatedly and prints every change in how an agent is treated, or a score change of --min-score-delta points or more. With --interval 0 it runs once and compares with the --state file, which suits cron.
